### 1. 模型提供商（自定义 API）
- 「我的 → 模型与额度」改为「模型与提供商」入口，进入提供商列表页（玻璃大卡片列表，分框摆放风格，不要一长条后台列表）。
- 支持新建 / 编辑 / 启用禁用 / 删除（删除前确认）/ 复制 / 导入导出（JSON）提供商。
- 每个提供商字段：名称、图标（自动按类型匹配官方图标，可换）、协议类型、Base URL、API 路径、API Key、是否启用、模型列表、高级设置。
- 协议类型至少：OpenAI 兼容（Chat Completions）、OpenAI Responses、Anthropic Messages、Google Gemini、DeepSeek 官方（OpenAI 兼容但有专用余额接口和缓存字段）、OpenRouter。预置模板：DeepSeek、OpenAI、Anthropic、Gemini、OpenRouter、硅基流动、自定义中转站（OpenAI 兼容）。选模板自动填 Base URL 和路径。
- 「拉取模型」：OpenAI 兼容走 GET {base}/models；Anthropic 走 /v1/models；Gemini 走 /v1beta/models。拉回后让用户勾选要加入的模型。也可手动添加模型。
- 每个模型可编辑：显示名、模型 ID、能力（视觉、工具调用、推理/思考）、上下文长度、思考档位支持方式（见第 2 条）、单价（每百万输入 / 缓存命中输入 / 输出 Token 的价格，可留空，币种可选 ¥/$）、收藏。
- 「测试连接」：样稿阶段没有后端，浏览器直连中转站多数会遇到跨域（CORS）被拦。所以样稿里：先做真实请求尝试（带超时 8 秒）；失败时按原因给短中文提示，绝不弹英文原始报错或卡死：网络不通 / 跨域被拦（「浏览器不能直接连这家，接上服务器后就能用」）/ Key 不对（401/403）/ 地址或路径不对（404）/ 额度用完（402/429 余额类）/ 请求太频繁（429）/ 服务器错误（5xx）/ 超时。把这套错误分类写成一个独立函数 classifyApiError，后端阶段复用。
- 余额查询：只对有官方接口的类型开启（DeepSeek GET /user/balance；OpenRouter GET /api/v1/credits；其他默认关闭并标「这家不支持查询余额」）。查询失败时在分组标题上只显示小灰字「余额暂不可查」，不要出现「Error: Request to /v1/credits failed: 404」这种字样。
- API Key 安全：样稿里存 localStorage，界面始终掩码，导出提供商 JSON 时默认不带 Key（勾选才带，并提示风险）。在 PROVIDERS_DESIGN.md 写明：正式版 Key 存 VPS 后端，浏览器不直接拿 Key 发请求，所有模型请求经后端转发（同时解决跨域）。
- 官方图标：用 MIT 许可的 @lobehub/icons-static-svg（npm 可装，当前 1.102.0），只把实际用到的约 15–25 个 SVG（DeepSeek、OpenAI、Claude/Anthropic、Gemini、Google、OpenRouter、硅基流动 SiliconCloud、Qwen、Kimi/Moonshot、智谱、豆包/火山、Grok/xAI、Mistral、Meta、通用中转站等）复制进 src/icons/ 并在构建时内联，不要把整个包打进 dist。按模型 ID 关键词自动匹配图标（如含 deepseek→DeepSeek，claude→Claude，gemini→Gemini，gpt/o1/o3/o4→OpenAI，qwen→Qwen…），匹配不到用中性字母圆形。图标放在玻璃小圆底上，和主题协调。在 THIRD_PARTY_NOTICES.md 写明来源和 MIT 许可。

### 2. 思考档位（专业处理，不能报错）
- 档位：关闭 / 自动 / 低 / 中 / 高（某些模型可额外显示「最高」）。
- 每个模型有「思考方式」字段，决定档位怎么翻译成请求参数（写成一个独立函数 buildReasoningParams(model, level)，后端复用）：
  - none：不支持，界面档位按钮置灰并写「这个模型不能调思考深度」，请求里绝不带任何思考参数。
  - openai_effort：reasoning_effort = low/medium/high（Responses 协议用 reasoning.effort）。
  - anthropic_budget：thinking = {type:"enabled", budget_tokens}，低/中/高 对应约 2048/8192/24576，并保证 max_tokens 大于 budget；关闭时不带 thinking。
  - gemini_budget：generationConfig.thinkingConfig.thinkingBudget（低/中/高 约 1024/8192/24576，自动 = -1，关闭 = 0 仅在模型允许时）；新模型可用 thinkingLevel。
  - deepseek：按官方方式处理（思考模式通过模型或 thinking 参数开关，DeepSeek 不支持细分档位时只给「关闭 / 开启」两档，不要假装有低中高）。
  - openrouter：reasoning = {effort} 或 {max_tokens}。
  - relay_suffix：部分中转站用模型名区分（如 xxx-thinking），这种情况档位只是切换到对应的模型 ID。
- 兜底：如果服务器因为思考参数返回 400（参数不支持），自动去掉思考参数重试一次，并在这条回复下方小字提示「这家不支持调思考深度，已按默认回复」，不要让聊天失败。样稿里用模拟函数演示这条流程。
- 位置：聊天页输入框上方 / 左侧工具位加一个小灯泡按钮（和现有工具胶囊同一排，图标线条风格），显示当前档位的小字（如「高」）；点开是底部玻璃弹层「思考深度」，分段滑杆 + 当前档位大字 + 一句说明。如果聊天页空间不够，就把不常用的工具收进输入框左边的「+」面板，只留灯泡和最常用的一两个，保证一行不挤。模型的默认档位在模型编辑页设，聊天里改的只影响这场聊天（问是否设为默认，和用户设定同样的交互）。
- 回复里的「思考过程」折叠显示（默认收起，一行「想了 N 秒」），提供商高级设置里有「回传历史思考过程」开关。
